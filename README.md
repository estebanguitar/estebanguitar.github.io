# Interior Compare

가구를 조건별로 모아 한눈에 비교하는 정적 웹 서비스.

👉 **https://estebanguitar.github.io**

소파 94 · 침대 202 · 식탁 100, 총 396건의 실측 치수·가격·소재·브랜드를
직접 수집하고 검증해 필터링 가능한 형태로 정규화했습니다.

## 왜 백엔드를 두지 않았나

데이터가 **읽기 전용이고 갱신 주기가 길다**는 점이 설계의 출발점이었습니다.

- 서버를 두면 월 고정비가 발생하는데, 트래픽 대비 이득이 없음
- 상품 데이터를 JS 객체로 인라인 → 첫 페인트 이후 추가 네트워크 요청 0
- GitHub Pages + CDN 캐싱으로 운영비 **0원**, 가용성은 GitHub에 위임
- **트레이드오프**: 상품 추가·수정 시마다 재배포가 필요하다.
  갱신 주기가 짧아지면 이 구조는 깨진다.

## 데이터 파이프라인

```
수집 → URL·이미지 유효성 검증 → 치수 정규화 → 중복·이상치 제거 → 인라인 번들
```

- 상품 URL과 이미지 링크를 전수 검증해 죽은 링크를 제거
- 원형·원목처럼 비교 축이 다른 품목은 의도적으로 제외해 비교 가능성을 확보
- 카탈로그 PDF(225MB)에서 타일 이미지 955장을 추출, 캡션 포함 크롭 227건을 자동 트리밍
  (타일 비교 페이지는 현재 네비게이션에서 내려둠)

## 구조

```
index.html            진입점
nav.js                Web Components 기반 공통 네비게이션
sofa-compare.html     소파 94
bed-compare.html      침대 202
table-compare.html    식탁 100
```

빌드 도구 없음. `.nojekyll`로 Jekyll 파이프라인을 끄고 정적 파일을 그대로 서빙합니다.

## 한계

- 상품 데이터가 **수동 수집**이라 스케일이 안 된다. 크롤러 미구현
- 단일 HTML 파일이 150~325KB로 커져 코드 분할이 필요한 시점
- 테스트 없음
- `index.html`의 meta description이 구버전 문구(의자 포함)로 남아 있음
